# Wiki Schema

## 目标与权限

本目录是 Agent 维护、用户审查的百科式知识文章与语义关系网络。原始来源是当前 Vault 中 `wiki/` 外的 Markdown，默认只读；普通写入只进入本目录。Schema 变更、删除、合并和来源修改必须逐项批准。

取消或否决任何写入方案时默认零写入：不创建 ingest、不追加 log、不更新 index。只有用户在取消后另行批准审计记录，才能写一份空 `outputs` 的例外记录。

## 目录与页面类型

```text
wiki/
├── schema.md
├── index.md
├── log.md
├── concepts/
├── claims/
├── domains/
├── syntheses/
├── ingests/
└── summaries/
```

- `concept`：完整解释定义、意义、机制、边界、实例和来源视角的概念文章。
- `claim`：展开前提、论证、证据、反证、竞争解释和状态的主张文章。
- `domain`：呈现知识范围、主题脉络、导航路径、争议和缺口的全景文章。
- `synthesis`：跨多个来源或页面形成证据链、分歧、增量推论和开放问题的综合文章。
- `summary`：长而复杂的单一来源确有独立总结价值时使用，保留原文结构、论证和关键细节；不是核心图节点。
- `ingest`：获批执行后的方案、决策和实际改动记录，不是知识结论。

新建前搜索 index、标题、标签和正文。只有知识单元会被多处引用、持续演化、需要独立追踪证据或承担明确导航/综合职责时才建页。

## 内容充分性

坚持“文章优先”：核心页首先应当是一篇无需遍历图谱也能理解的知识文章，其次才是图中的节点。正文必须回答标题承诺的知识问题，交代必要背景与语境，展开机制或论证，呈现边界、反例或竞争解释，并给出读者可使用的实例、含义或导航。语义关系、链接清单、frontmatter 和演化记录都不能替代正文。

每个页面同时满足以下质量门：

1. **独立可读**：开头给出中心定义或结论，随后形成连续解释；读者不打开相邻页也能理解本页主线。
2. **来源保真**：区分来源作者、用户观点与 Agent 综合；把重要判断追溯到具体来源，保留冲突、条件和不确定性，不用常识填充来源没有支持的细节。
3. **跨来源增量**：使用多个来源时，明确各来源的独特贡献、一致、分歧与互补，以及组合后才出现的新理解；只有单一来源时，说明可概括的范围与不能外推之处。
4. **丰富而紧凑**：用描述性三级标题、连贯段落和必要的列表或表格组织内容。每一节增加定义、因果、证据、比较、例证、限制或推论之一；删除同义复述和只为增长篇幅的填充。

`lint_wiki.py` 用“内容单位”提供保守的薄页预警：每个 CJK 字符或每个以空白分隔的拉丁词计一个单位；frontmatter、标题、代码块、裸 URL、语义关系行、演化记录和模板占位符不计。机械预警线不是合格线，达到数字仍需通过上述质量门。

| 页面类型 | 机械预警线（内容单位） | 常见规划区间 | 应覆盖的内容模块 |
| --- | ---: | ---: | --- |
| `concept` | 1200 | 1600–2800 | 核心问题、定义与意义、机制或组成、边界与反例、相邻概念、应用或实例、来源视角与综合 |
| `claim` | 1400 | 1800–3200 | 明确命题、术语与范围、前提、论证链、支持证据、反证与例外、竞争解释、当前状态 |
| `domain` | 2200 | 3000–5200 | 范围与中心问题、全景概述、主题脉络、主要争议、导航路径、来源覆盖、知识缺口 |
| `synthesis` | 2600 | 3400–6000 | 综合问题、材料范围、中心结论、来源贡献、证据链、一致与分歧、竞争解释、新推论、缺口 |
| `summary` | 1400 | 1800–3500 | 来源语境与结构、关键内容、主要论证与证据、重要细节、限定与遗漏、可复用连接 |

覆盖表中所有适用模块；材料确实不支持的模块不虚构。新建或实质更新页低于预警线时，先尝试合并到已有文章或补充有来源依据的内容；仍需保留独立页面时，在对应 ingest 的“矛盾、不确定性与限制”记录“来源受限例外”、实际内容单位、缺失模块和后续补全条件。

## Frontmatter

所有知识页包含：

```yaml
---
type: concept
tags:
  - 示例标签
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "[[notes/原始笔记.md]]"
---
```

- `tags` 为单层块状列表。优先使用 1～3 个稳定检索标签；技术名使用官方英文，避免同义、大小写和连接符变体，也不重复 `type`。
- 新写入的 `sources` 每项使用带引号的 Obsidian Wiki 链接，如 `"[[notes/原始笔记.md]]"`，因此可从属性直接跳转。链接目标必须是 Vault 内、位于 `wiki/` 外且存在的 Markdown；URL 只写正文。旧版 Vault 相对路径继续可读并产生迁移警告，但不得继续新增。
- `created` 保持首次日期；`updated` 只随知识内容的实质变化更新。

`claim` 增加：

```yaml
state: proposed
origin: synthesis
```

`state` 为 `proposed`、`supported`、`contested`、`superseded`；`origin` 为 `personal`、`source`、`synthesis`、`conversation`。

`synthesis` 增加 `state`，值为 `provisional`、`stable`、`contested`。

`ingest` 使用：

```yaml
---
type: ingest
status: completed
review: accepted
created: YYYY-MM-DDTHH:MM:SS+08:00
sources:
  - "[[notes/原始笔记.md]]"
outputs:
  - wiki/concepts/某个概念.md
---
```

`status` 为 `completed`、`partial`、`cancelled`；`review` 为 `accepted`、`revised`、`rejected`。`cancelled` 与 `rejected` 只兼容旧记录或用户另行批准的例外审计记录，并必须使用 `outputs: []`。普通取消或否决不创建记录。

### Sources 兼容与迁移

Lint 同时解析新版 Wiki 链接和旧版 Vault 相对路径。只要旧路径仍指向 Vault 内、`wiki/` 外的现有 Markdown，它就是兼容警告而不是证据错误；路径缺失、越界、进入 `wiki/` 或不是 Markdown 时仍为错误。

使用 `python '<skill-dir>/scripts/migrate_sources.py' <vault>` 先预览、确认后再以 `--apply` 批量迁移。迁移仅把旧列表值改为带引号的 Wiki 链接，不改变知识内容或 `updated`；任何无效待迁移目标都会阻断整批写入。迁移成功后记录 migration 日志并重新运行 lint。

## 语义关系

核心页在固定的 `## 语义关系` 中把当前页作为主语，每行写一条有向边：

```markdown
- **supports** → [目标主张](../claims/目标主张.md)：说明为什么是该关系以及依据。
```

| 类型 | 当前页指向目标页的含义 |
| --- | --- |
| `supports` | 为目标主张或综合提供支持 |
| `challenges` | 提供反证、冲突或竞争解释 |
| `qualifies` | 限定目标的范围、条件或强度 |
| `depends-on` | 以目标作为前提、机制或必要背景 |
| `causes` | 对目标具有有依据的因果作用 |
| `applies-to` | 把当前知识应用于目标问题或场景 |
| `part-of` | 当前节点是目标节点的一部分 |
| `distinguishes-from` | 说明当前节点与目标节点的关键差异 |
| `organizes` | 当前 domain 组织或导航目标节点 |
| `synthesizes` | 当前 synthesis 综合目标节点 |
| `supersedes` | 当前 claim 取代目标 claim |

- 不使用无语义的 `related-to`。没有可靠类型或理由时不建边。
- 索引、证据、演化记录和正文中的普通链接不算语义边。
- 自环、重复“类型 + 目标”、指向 summary/ingest/基础文件的边无效。

图谱不设置全局最小出边或最小邻居数。只有入边、只有一个邻居、暂时孤立或存在多个弱连通分量都不是硬错误；lint 只把孤立节点、分量分离以及与页面职责不一致的稀疏关系作为人工复核警告。`domain` 通常应以 `organizes` 导航实际覆盖的核心页，`synthesis` 通常应以 `synthesizes` 指向它实际综合的多个核心页，但缺少这些边不自动证明内容无效。关系的真实性、类型和方向优先于连接数量；不得为消除警告虚构边或机械补反向边。

## 正文结构

知识页文件名等于 H1 标题。保留对应模板的以下二级标题，以便 lint：

- concept：定义、边界、语义关系、依据与来源、不确定性、演化记录。
- claim：主张、含义与适用范围、支持证据、质疑与反例、语义关系、当前状态、不确定性、演化记录。
- domain：范围、知识地图、核心问题、主要页面、语义关系、依据与来源、知识缺口、演化记录。
- synthesis：综合结论、连接如何形成、证据链、竞争性解释、语义关系、不确定性与缺口、演化记录。
- summary：为什么需要独立摘要、来源概览、关键内容、关联、依据与来源、局限、演化记录。
- ingest：结果摘要、输入来源、各来源关键点、拟议连接及依据、接受/调整/放弃、用户纠正、实际改动、矛盾/不确定性/限制、外部来源、检查。

模板的必需二级标题保持稳定，三级标题作为文章模块按材料保留或调整。每个新建或实质更新的知识页在“演化记录”链接对应 ingest。关键判断追溯到原始笔记或正文外部来源。外部来源记录名称、完整 URL、访问日期及其支持、质疑或补充的内容。

## Index 与 Log

Index 按 Domains、Concepts、Claims、Syntheses 分区；每个核心页恰好一项，格式为“链接 — 一句话说明”，claim 和 synthesis 同时写当前状态。Ingests 与 Summaries 只保留目录入口。

Log 只追加已经发生的 ingest、产生写回或重要发现的 query、lint、schema、migration 和 correction。普通查询、未执行方案、取消和否决不记录。标题使用：

```text
## [YYYY-MM-DD HH:MM] ingest | 简短标题
```

## 工具边界

第一版使用 index、文本搜索和语义边遍历。Embedding、向量数据库或其他索引设施只在出现可复现的漏召回或导航失败后，作为独立 schema 与工具变更提出。

每次实际写入后同步 index 与 log，运行结构 lint，再完成语义审查。不得自动暂存、提交或推送 Git。
