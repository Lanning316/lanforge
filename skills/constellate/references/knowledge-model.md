# 知识模型

把原始笔记中的事实、个人语境、论证和思考钩子重组为可独立阅读的知识文章，再以有类型的语义边连接这些文章；不要镜像原 Vault。

## 文章优先与页面粒度

让每个核心页围绕一个稳定的读者问题形成完整文章。把回答该问题所需的定义、背景、机制、证据、边界、反例、实例和不确定性留在同一页；把可复用但彼此独立演化的知识问题拆成页面。语义关系负责导航和表达可审查的边，不替代正文中的解释、过渡和论证。

只在内容拥有独立的演化、证据、争议或导航职责时拆页。优先创建较少而充分的页面，并在其中组织相对原子的事实与判断；不要把每个术语、单条观察或一段摘要都升级为独立节点。`domain` 与 `synthesis` 提供更长的全景和综合，但不能补偿 concept 或 claim 自身正文过薄。

## 节点类型

- `concept`：用一篇文章解释可复用概念的定义、意义、机制或组成、边界、相邻概念、实例和来源视角。只在会被多个页面引用或持续演化时建页。
- `claim`：用一篇论证文章保存需要独立追踪的判断、前提、适用范围、证据链、反证、竞争解释与状态。
- `domain`：用全景文章组织一个知识范围、核心问题、主题脉络、主要页面、争议和缺口；普通分类目录不构成 domain。
- `synthesis`：用综合文章跨多个来源或节点形成更高层解释，呈现来源贡献、证据链、一致与分歧、竞争解释、新推论和未解决问题。
- `summary`：长而复杂的单一来源确需独立总结时，用文章保留其结构、论证、关键细节和局限；它不是核心图节点。
- `ingest`：获批执行后的决策与改动记录；它不是知识结论。

### Claim 状态

`origin` 使用 `personal`、`source`、`synthesis`、`conversation`，分别表示用户表达、来源作者主张、跨来源归纳和对话中形成的判断。

`state` 使用 `proposed`、`supported`、`contested`、`superseded`。来源数量不自动决定状态；证据决定认知状态。

### Synthesis 状态

`state` 使用 `provisional`、`stable`、`contested`。写得完整不等于稳定；新证据可以使状态回退。

## 建页与更新

新建前搜索 index、标题、标签和正文。满足至少一项才新建：会被多处引用、会随来源持续演化、需要独立追踪证据或争议、承担明确导航职责、形成真正的跨来源综合。新页还必须拥有足够材料回答一个完整知识问题；否则更新现有文章的相关章节，或把内容留在来源中。

- 补充同一概念、synthesis 或 claim：原地更新并记录演化。
- 新判断与旧 claim 不兼容：新建 claim，并把旧页标为 `contested` 或 `superseded`。
- 保留有认知价值的争议；不要为表面一致删除它。

## 关系判断

适用 schema 是关系格式与受控类型的唯一权威。为每条候选边判断：当前页为何是主语、目标为何是宾语、最具体的关系类型是什么、来源或正文中的哪项内容支持该关系。

没有足够依据判断类型或方向时不创建边，把候选关系留在 ingest 的放弃项或不确定性中。对称关系仍从当前页视角表达；不要为了让页面拥有出边、增加邻居数或连接分量而机械复制反向边或虚构关系。只有入边、只有一位邻居或暂时孤立都不是全局硬错误；如实保留稀疏结构，并把值得研究的连接列为待研究项。

多个弱连通分量不自动等于错误。先判断它们是否确属独立知识域，再决定补桥接节点或关系；不能虚构连接。

## 证据契约

- 新写入的 `sources` 只列可直接跳转的 Obsidian Wiki 链接，例如 `"[[notes/原始笔记.md]]"`；目标必须是 Vault 内、`wiki/` 外的原始 Markdown。旧版相对路径只用于读取兼容，不继续新增；lint 将其标为待迁移而不是证据错误。
- Wiki 节点是理解入口，不是最终证据。关键判断追溯到原始笔记或正文记录的外部来源。
- 经授权使用的外部来源在正文记录名称、完整 URL、访问日期及其证据作用。
- 对话形成且尚无原始来源的判断使用 `origin: conversation` 和合适状态。
- 每个新建或实质更新的知识页在“演化记录”链接获批执行所产生的 ingest。

完成标准：每个新建或实质更新的核心节点都达到建页门槛，按适用 schema 覆盖内容模块并形成独立可读的文章，证据可追溯，跨来源增量与来源内容可区分；每条语义边格式有效且有依据，图谱稀疏性不会诱导补写虚构关系。
