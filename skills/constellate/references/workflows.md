## 命令解析

把自然语言映射到一个主操作：

```text
/constellate --init [Vault 路径]
/constellate --ingest 路径一 [路径二 ...]
/constellate --query 问题
/constellate --lint [wiki 内范围]
/constellate --schema 变更意图
```

- `--apply`：跳过普通新增与更新的二次确认。
- `--web`：授权本轮联网。
- `--offline`：禁止本轮联网；与 `--web` 同时出现时请求用户选择。

路径相对于 Vault 根目录解析。Ingest 只接受 Vault 内、`wiki/` 外的 Markdown。多个主操作、未知参数、歧义路径或互斥参数必须先澄清。

## 初始化

1. 读取 [schema-reference.md](schema-reference.md) 和 `assets/wiki/schema.md`，展示将创建的目录、文件与关键规则。
2. 未带 `--apply` 时等待确认；取消或否决时按 SKILL 的零写入终点结束。
3. Wiki 不存在时运行 `python '<skill-dir>/scripts/init_wiki.py' <vault>`。
4. Wiki 已存在时先用同一命令获取只读兼容性报告。用户批准全部缺失项后追加 `--add-missing`；只批准部分时再追加 `--only schema.md,claims`。
5. 运行 lint，汇报创建项、已有项、未批准项和异常项。

完成标准：只创建获批的缺失项，没有覆盖已有文件，lint 无错误。

## Ingest

### 1. 确定范围

只读取用户指定的文件或目录。可以根据链接、标签、标题和关键概念自动读取少量明显相关笔记；扩大到整个目录或 Vault 前先确认。多来源逐篇保留语境，再整体连接；来源过多时拆批。

完成标准：每个纳入来源都已读取，范围扩张均已授权，没有把 Wiki 或 Vault 外文件当作正式来源。

### 2. 分析图变更

逐篇区分用户判断、来源作者主张与原始记录，提取可复用概念、可检验主张、论证结构、例证和限制。整体检查现有文章、证据状态、矛盾、标签词表和候选语义边；按 [knowledge-model.md](knowledge-model.md) 作语义判断，并用适用 schema 验证每个拟建页面的内容契约与关系格式。连接数量只用于发现可能遗漏，不作为建页或写入的硬门槛。

为每个拟创建或实质更新的知识页先写“文章简报”：页面要回答的读者问题、中心结论、适用内容模块、各来源的独特贡献、跨来源一致/分歧/互补、相较现有 Wiki 的新增理解、计划篇幅与潜在来源受限例外。先决定现有文章能否承载这些内容；只有独立建页更有利于理解和持续演化时才新建。

默认不创建单篇摘要。只有来源长且复杂，并且独立摘要能显著降低后续理解成本时才提出 `summary`。

完成标准：每个拟创建或实质更新页都有可审查的文章简报、来源贡献、跨来源增量、适用内容模块、证据和有依据的具体语义边；稀疏或暂时没有关系时如实说明，依据不足的内容与关系已明确放弃或标为待验证。

### 3. 提交一次方案

展示来源关键点、拟创建/更新页面及其文章简报、每条重要边及依据、图谱稀疏性提示、内容充分性计划、矛盾、不确定性、放弃项、标签变化、外部检索建议和检查计划。未带 `--apply` 时等待确认。

用户取消或否决时立即结束，不创建 ingest、不写 log、不更新 index、不落盘任何分析。若用户另行要求保留审计记录，把记录范围作为新方案再次确认。

完成标准：方案已获批准，或任务以“未写入任何文件”结束。

### 4. 写入获批方案

1. 使用 [schema-reference.md](schema-reference.md) 指定的模板和适用 schema 的内容契约更新或创建页面。先写成可独立阅读的知识文章，再按关系契约写 `## 语义关系`；关系清单不能替代正文解释。
2. 创建一份 ingest，记录方案、用户纠正、接受/放弃的边、实际输出和限制。
3. 在所有实质变化页面的“演化记录”链接本次 ingest。
4. 同步 index，向 log 追加一次完成事件。
5. 运行 lint，修正机械错误；逐页处理 `content-thin` 等内容警告，低于预警线时扩充有依据的内容，或在 ingest 中记录来源受限例外与缺失模块；再查看实际差异与 ingest `outputs` 是否一致。

完成标准：获批页面、ingest、index 和 log 相互一致；所有新建或实质更新页独立可读，覆盖适用内容模块并达到内容契约，或记录了不以虚构和填充换篇幅的来源受限例外；所有已写入语义边真实、有效且有依据，稀疏节点已如实保留或说明，lint 无错误。

## Query

1. 读取 schema 与 index，用文本搜索定位起点，再沿语义边的方向和类型扩展少量相关节点。
2. 需要核对关键判断时回到 `sources` 指向的原始笔记；Wiki 自身不能充当最终证据。
3. 先回答问题，区分来源内容、用户观点和 Agent 综合。重要事实与主张附 Wiki、原始笔记或已授权外部来源；无法追溯时标为待验证。
4. 默认不写回。只有形成新的跨来源综合、改变 claim、发现长期有价值的边或能把现有薄页补成完整知识文章时才提交写回方案；写回同样执行文章简报与内容契约，取消或否决该方案时零写入。

第一版使用 index、文件搜索和语义边遍历。只有规模导致明显漏召回或导航失效时，才把 embedding、向量库或其他索引升级作为独立 schema 与工具变更提出。

完成标准：答案可追溯，关系路径清楚，未获批准的写回没有落盘。

## Lint

1. 运行 `python '<skill-dir>/scripts/lint_wiki.py' <vault> [--scope <范围>]`，把结果作为确定性机械层。
2. 审查需要判断的知识层：页面能否独立回答标题承诺的问题、适用内容模块是否覆盖、篇幅是否来自有用解释而非重复填充、来源贡献与跨来源增量是否明确、近义或重复节点、关系类型是否准确、理由是否真的支持该边、证据与 claim 状态是否匹配、矛盾、过时主张、薄弱 synthesis、domain 导航质量和疑似虚构的凑数连接。
3. 审查图层：弱连通分量和孤立节点是否合理、桥接节点是否确有证据、关系方向是否便于查询。无出边、邻居少或分量分离本身不是错误；只报告有事实依据的遗漏候选，不为改善图指标补边。
4. 审查数据层：缺失概念、未覆盖来源、外部来源可信度和值得继续研究的证据缺口。
5. 按“确定的机械问题”“需要判断的知识问题”“图结构问题”“值得继续研究的数据缺口”分组；默认只报告修复计划。
6. `--apply` 只修复普通新增和更新；删除、合并和 schema 变更仍单独确认。用户否决修复方案时零写入。

遇到 `source-legacy-path` 时保持查询与证据追溯可用，不把旧格式当作错误，也不在普通 lint 中自动改写。需要迁移时，先运行 `python '<skill-dir>/scripts/migrate_sources.py' <vault> [--scope <范围>]`；向用户展示完整预览并获得明确批准后才追加 `--apply`。迁移器遇到任一无效旧目标时整体停止。执行后追加一条 migration 日志并重新运行 lint；不更新知识页的 `updated`。

完成标准：脚本已实际运行；每个 `content-thin` 警告都对应具体缺失模块、可依据来源扩充的内容或来源受限例外；旧版 source 已保持可读并给出可执行迁移路径；各问题归入唯一类别，报告区分错误、警告与人工判断，且未越权修复。

## Schema 演化

1. 用真实案例说明现有 schema 为什么不足，列出具体规则、影响范围、迁移、回退和验证方法。
2. 等待明确批准；`--apply` 不替代批准。取消或否决时零写入。
3. 只修改获批的 `wiki/schema.md` 并记录 schema 事件。
4. 若需迁移旧页面，另行提交迁移方案并再次确认。

完成标准：schema 变更与迁移分别获批并验证；未获批部分没有落盘。

## 删除与合并

逐项展示目标页、保留页、独有内容、所有入站边、普通链接和附件，再等待确认。执行后重新搜索引用，迁移来源与演化记录，同步 index、log 和 ingest；优先把被替代 claim 标为 `superseded`。交付时说明删除、保留、迁移和 Git 可恢复性。

完成标准：所有高影响项逐项获批，入站边与链接无断裂，lint 无错误。

## 联网与附件

联网后优先使用原始、官方或学术来源。正文记录名称、完整 URL、访问日期和证据作用，不写入 `sources`。只有获得联网授权后才检查远程链接状态。

保持原附件不变；只有附件承载正文未表达的信息且任务确实需要时才读取。无法读取时列为限制，不根据文件名猜测。
