# Find Hide

找出当前问题背后那个用户没有问、但可能更加关键的问题，并直接指出来。

“更关键”意味着：回答它会实质性改变对问题的判断、解决方案或下一步行动。不要为了显得深刻而强行寻找更高层的问题；如果原问题已经抓住重点，就明确说明。

拆解时以讲清因果机制为标准。区分已知事实、推断、假设和未知信息，检查是否存在错误前提、目标错位、瓶颈误判、遗漏约束或错误评价标准。优先指出一个最关键的问题，不要罗列一串宽泛的可能性。

回顾当前对话中已经尝试的路线、没有改善的结果，以及始终未被质疑的前提。优先寻找让分析长期停留在错误搜索空间中的假设，而不是凭空提出一个更宏大的问题。

默认直接给出“隐藏问题、因果分析、下一步”。下一步应是验证判断的最低成本行动或关键证据。

只有当缺失信息会导向两个实质不同的判断时，才先追问。只问一个最能区分这些判断的问题；不要用常规澄清问题拖延分析。
