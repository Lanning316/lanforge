# 新手排错指南

在用户要求诊断错误或异常行为时使用。诊断默认只读；用户没有要求修复时，不修改代码、配置或依赖。

## 目录

1. 收集现象
2. 缩小范围
3. 建立假设
4. 安全验证
5. 形成结论
6. 常见故障类型

## 1. 收集现象

- 完整错误信息和堆栈是什么？
- 哪个操作触发，是否稳定复现？
- 发生在构建、启动、运行、测试还是部署阶段？
- 期望行为和实际行为分别是什么？
- 最近有哪些相关改动？

先保存原始错误文本，不要只依赖用户对错误的概括。

## 2. 缩小范围

按成本从低到高检查：

1. 阅读堆栈指向的文件、符号和调用方。
2. 查看相关配置定义与加载位置，但遮蔽敏感值。
3. 查看 `git diff` 和近期相关提交。
4. 搜索错误文本、错误类型和返回位置。
5. 阅读覆盖该路径的测试。
6. 确认问题是否只在某个环境、输入或并发条件下发生。

命令行环境可用时，优先使用 `rg` 搜索文本和符号。不要把安装依赖、删除缓存或重建环境当作第一步。

## 3. 建立假设

每个假设写清：

| 假设 | 支持证据 | 反证 | 下一步只读检查 |
| --- | --- | --- | --- |
| {可能根因} | {日志、代码、测试} | {不符合之处} | {检查动作} |

常见类别：

- 输入或状态不满足前置条件。
- 类型、空值或边界处理错误。
- 配置缺失、覆盖顺序或环境差异。
- 依赖版本、构建或生成文件不一致。
- 网络、权限、超时或下游不可用。
- 并发、重试、缓存或数据一致性问题。
- 业务规则本身与预期不一致。

## 4. 安全验证

优先采用不会改变工作区或外部状态的方法：

- 阅读测试和调用链。
- 运行已有的最小相关测试。
- 使用项目已有的只读诊断或静态检查命令。
- 对比已知正常输入与失败输入。
- 查看日志、指标或跟踪信息。

需要编辑代码、调整配置、安装依赖、清缓存或调用生产系统时，先确认这属于用户请求并说明影响。

## 5. 形成结论

使用以下结构：

```markdown
## 结论
{最可能根因；若未证实，明确写“当前最可能”}

## 证据
- `{文件或日志位置}`：{支持什么结论}

## 排除项
- {检查过但不支持的假设}

## 建议验证
1. {最小、安全的验证动作}

## 修复方向
{仅在用户要求修复时给出或实施}
```

## 6. 常见故障类型

| 现象 | 常见原因 | 首先检查 |
| --- | --- | --- |
| 找不到模块或依赖 | 路径、安装状态或版本不匹配 | 依赖清单、锁文件、导入路径 |
| 连接被拒绝 | 服务未启动、地址错误或端口不可达 | 启动日志、配置来源、目标状态 |
| 域名无法解析 | 地址错误或网络环境问题 | 配置使用点、网络和代理设置 |
| 请求超时 | 下游缓慢、超时过短或阻塞 | 调用链、超时配置、耗时日志 |
| 未授权或禁止访问 | 身份、权限或凭据范围不正确 | 鉴权入口、权限检查、凭据来源 |
| 空值或类型错误 | 输入未校验、状态未初始化 | 堆栈首个项目代码位置、调用方 |
| 测试通过但运行失败 | 环境、数据或真实依赖不同 | 测试替身、配置差异、部署日志 |
| 重复执行或数据冲突 | 重试、并发或幂等处理缺失 | 请求标识、事务边界、去重逻辑 |
