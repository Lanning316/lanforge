# Git 演进分析

只在用户明确询问设计原因、演进、文件历史或重构过程，或者当前代码无法解释关键设计理由时读取。目标是为新人解释“为什么变成现在这样”，不是进行全仓库考古。

## 1. 先确认当前形态

在查看历史前，先定位目标模块或文件的当前职责、入口、核心对象、调用方、下游和相关测试。历史必须解释当前仍存在的结构，而不是脱离现状复述旧提交。

将历史范围限定为：

- 用户指定的模块目录或文件。
- 当前入口、核心模型和关键测试等少量锚点。
- 为验证一次移动、重命名或跨模块重构而必须补充的相邻路径。

默认只使用当前检出版本可达的本地历史。不自动 fetch，不切换分支，不使用 `--all` 扩展到其他引用；用户明确要求时再扩大范围。

## 2. 检查历史是否可靠可用

先进行只读检查：

```text
git rev-parse --is-inside-work-tree
git status --short
git rev-parse --is-shallow-repository
git log -1 --format="%h %ad %s" --date=short
```

- 不是 Git 仓库：说明无法还原提交演进，继续用当前代码、测试和文档回答。
- 浅克隆：明确历史可能缺少起点和早期重构，不把最早可见提交称为“首次引入”。
- 有未提交改动：把工作区现状与 `HEAD` 历史分开描述，不把未提交代码归因于某个提交。
- squash、提交说明贫乏或历史被重写：只能确认补丁展示的变化，设计动机通常标为推测或未知。

## 3. 从候选提交收敛到关键里程碑

模块目录先查看路径级摘要和变更规模：

```text
git log --date=short --format="%h%x09%ad%x09%s" --stat -- <module-path>
```

单文件优先追踪重命名：

```text
git log --follow --date=short --format="%h%x09%ad%x09%s" -- <file-path>
```

目录级 `--follow` 不可靠。模块曾移动或重命名时，从当前入口、核心模型和关键测试分别追踪，并用以下检查验证候选提交：

```text
git show --find-renames --find-copies --stat <commit>
git show --find-renames --find-copies --format=fuller <commit> -- <relevant-paths>
git diff --find-renames <older>..<newer> -- <relevant-paths>
```

只有在解释某一行当前约束的来源时才使用 `git blame -L`，然后继续查看对应完整提交。不要把 blame 的作者或提交单独视为设计负责人或设计原因。

优先选择能改变新人心智模型的提交：首次出现、修复重要缺陷、增加兼容或安全约束、改变边界或依赖方向、拆分/合并职责、增加关键测试。文案调整和机械格式化通常跳过。

候选已经足够回答起点、关键转折和当前护栏时停止；不要为了完整而逐条读取全部历史。

## 4. 证据分级

历史结论使用以下标签：

| 标签 | 可以声称什么 | 常见证据 |
| --- | --- | --- |
| 作者明确声明 | 提交作者或项目文档当时声称的目标或约束 | 提交正文、设计文档、仓库内关联说明 |
| 可观察演进 | 某段代码、测试、接口或边界在该提交中如何变化 | 补丁、测试变化、配置或迁移 |
| 推测 | 多项证据支持一种解释，但没有直接说明动机 | 结构变化、命名、相邻缺陷修复 |
| 未知 | 本地历史不足以支持原因或因果关系 | 缺失记录、squash、浅克隆、仓库外讨论 |

提交主题只能证明作者如何概括提交，不能自动证明全部设计意图。时间相邻不等于因果关系；merge 提交也可能只汇总其他提交。

## 5. 识别当前设计护栏

只有同时满足以下两项，才称为“修改时不要轻易破坏的设计护栏”：

1. 历史证据表明该变化在解决缺陷、兼容、安全、数据一致性或明确架构约束。
2. 当前代码、测试、接口、数据格式或配置仍然实施或保护该约束。

只满足历史证据时称为“历史设计意图，当前是否仍适用待确认”；只看到当前复杂实现但没有历史解释时称为“候选风险”。不要把所有遗留复杂度合理化。

## 6. 面向新人的输出

先用一小段说明当前模块是什么，再用少量里程碑回答：

1. **最初的问题**：最早可确认的职责和证据；浅克隆时改称“最早可见状态”。
2. **关键演进**：每个节点说明发生了什么、解决什么，以及可观察的代价或权衡。
3. **为什么是现在这样**：把历史节点连接到当前文件、接口和测试。
4. **修改护栏**：区分不要轻易破坏、可以安全调整、候选风险。
5. **未知项**：列出需要维护者、PR/issue 或更完整历史确认的问题。

历史证据至少包含短提交哈希、日期、主题和相关路径。存在符合项目约定且目标读者可访问的远程提交链接时可以使用；否则使用本地可搜索的提交标识。
