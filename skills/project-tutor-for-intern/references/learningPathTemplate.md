# 新人学习路径模板

在用户明确要求阅读计划、入职计划或阶段性练习时使用。计划应根据仓库规模、用户背景和当前任务调整，不承诺固定天数一定掌握项目。

## 第一阶段：能运行与定位

目标：知道项目如何启动，能找到主要入口和错误日志。

- 阅读根目录说明、构建清单和本地运行脚本。
- 在安全的本地或测试环境运行最小示例。
- 找到一个入口、一个配置使用点和一个相关测试。
- 记录仍依赖外部环境的部分。

验证：能够说明“从哪个入口启动、配置从哪里来、失败时先看哪里”。

## 第二阶段：建立全局地图

目标：能解释核心模块和一条代表性主链路。

- 识别 3–7 个核心模块。
- 选择一个有测试或文档支持的代表性场景。
- 从入口追踪到结果，记录关键文件和符号。
- 三跳以上时绘制一张简单链路图。

验证：不看代码也能复述模块职责和主链路；回到代码时能快速定位。

## 第三阶段：深入目标模块

目标：理解一个与当前工作直接相关的模块。

- 阅读公开入口、核心数据结构和主要实现。
- 找到直接调用方和下游依赖。
- 阅读正常路径、边界条件和失败路径测试。
- 找到一个已有扩展或类似实现作为参照。

验证：能够解释“为什么存在、谁调用、依赖谁、哪里最容易改错”。

## 第四阶段：完成低风险改动

目标：在明确影响范围后完成一个小改动。

- 先写出预期行为和验证方式。
- 搜索直接调用方、共享模型、配置和测试。
- 选择最小改动路径。
- 运行相关测试、静态检查和构建命令。
- 记录尚未覆盖的动态依赖或环境风险。

验证：能够说明改动证据、测试结果和剩余风险，而不只说“本地能跑”。

## 按项目形态调整重点

### 服务化系统

- 重点：入口、通信边界、超时、错误传播和可观测性。
- 实操：追踪一个外部请求到最终响应或异步结果。

### 多包或大型仓库

- 重点：包边界、共享库、构建图和受影响范围。
- 实操：选择一个共享符号，确认实际调用者和测试覆盖。

### 插件式系统

- 重点：扩展契约、注册机制、生命周期和隔离边界。
- 实操：比较两个最小插件实现，找出固定部分和可变部分。

### 配置驱动系统

- 重点：配置定义、加载、覆盖顺序、校验和动态更新。
- 实操：从一个配置项追踪到所有使用位置，不直接改生产配置。

### 事件驱动系统

- 重点：事件生产者、消费者、投递语义、重试和幂等。
- 实操：从事件产生追踪到最终状态变化，并记录失败处理。

## 每阶段自检

- [ ] 我能区分仓库事实、自己的推测和仍未知的内容。
- [ ] 我能给关键结论指出文件、符号、配置或测试依据。
- [ ] 我知道当前最重要的主链路，而不是试图读完所有文件。
- [ ] 我知道改动前要检查哪些直接依赖和共享契约。
- [ ] 我能提出具体问题，而不是只说“这个项目看不懂”。

## 求助策略

| 困难 | 先做什么 | 需要询问什么 |
| --- | --- | --- |
| 看不懂函数 | 看调用方、测试和数据结构 | 这个函数承担的业务边界是什么 |
| 不理解设计理由 | 查设计文档、注释和提交记录 | 当时有哪些约束或替代方案 |
| 环境跑不起来 | 对照文档、脚本和错误日志 | 缺少哪个外部依赖或权限 |
| 不确定改动范围 | 搜调用方、共享类型和配置 | 是否存在运行时注册或外部消费者 |
| 完全迷失 | 回到入口和代表性主链路 | 当前任务最小需要理解哪一段 |
