# 教程整体验收清单

确定性校验通过后使用。目标是发现脚本无法判断的事实、教学和维护问题。

## 目录

1. 范围与事实
2. 主线与结构
3. 源码证据
4. 受众与术语
5. 可维护性与安全
6. 可选内容

## 1. 范围与事实

- [ ] 教程开头说明讲什么、不讲什么。
- [ ] 源码基准是 commit 或“当前工作区快照”。
- [ ] 项目事实、作者推测和未知项清楚区分。
- [ ] 没有把通用架构知识冒充成当前项目的设计理由。
- [ ] 目标模块名称、路径和公开入口准确。

## 2. 主线与结构

- [ ] 阅读路线引用的标题真实存在。
- [ ] 主流程从入口到结果连续。
- [ ] 核心对象表与主流程使用相同名称。
- [ ] 异常路径和常见坑没有打断主线。
- [ ] 单文件只有一个文末总结；多文件每个实质性章节一个。
- [ ] 相邻章节或小节有自然过渡，不像孤立 FAQ 拼接。

## 3. 源码证据

- [ ] 所有本地相对链接都由校验脚本验证存在。
- [ ] 远程永久链接锚定 commit，而不是可变分支。
- [ ] 逐一抽查核心结论的路径、符号和行号。
- [ ] 代码片段与链接指向同一实现。
- [ ] 测试引用确实支持文档声称的行为。
- [ ] 无法验证的远程链接已在交付说明中注明。

脚本可以验证“文件存在”，但不能验证“这段代码真的支持这句话”，因此核心证据仍需人工逐项检查。

## 4. 受众与术语

- [ ] 新术语首次出现时解释。
- [ ] 同一概念在全文使用同一名称。
- [ ] 新人主线没有关键跳步。
- [ ] 有经验读者能快速找到边界、权衡和失败路径。
- [ ] 类比后指出了重要边界。
- [ ] 知识框没有重复主线内容。

## 5. 可维护性与安全

- [ ] 没有 `file:///`、用户目录或其他本机绝对路径。
- [ ] 没有密钥、令牌、连接串、个人数据或不必要的内部地址。
- [ ] 仓库相对链接没有逃出项目根目录。
- [ ] 没有残留模板提示、占位符或虚构示例。
- [ ] 更新教程不会要求无意义的空提交。
- [ ] 交付说明记录了未确认事实和链接限制。

## 6. 可选内容

仅在用户要求时检查：

### 面试 Q&A

- [ ] 问题对应正文已经解释的概念。
- [ ] 回答描述本项目行为，而不是只有教科书定义。
- [ ] 每个核心回答有源码或测试证据。
- [ ] 不鼓励读者虚构个人经历或项目贡献。

### 多文件教程

- [ ] README 中的章节链接全部存在。
- [ ] 章节顺序和阅读路线一致。
- [ ] 各章术语、源码基准和链接策略一致。
- [ ] 附录没有引入正文从未说明的核心机制。

全部适用条目通过后即可完成；是否提交 Git 由用户授权决定。
