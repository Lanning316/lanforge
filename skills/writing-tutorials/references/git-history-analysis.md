# Git 历史分析与教程写作

只在用户明确要求设计原因、演进、文件历史或重构过程，或者当前证据无法解释关键设计理由时读取。目标是增加一段可验证的演进解释，不是让所有教程默认扫描 Git。

## 1. 触发后先确认当前实现

先定位目标模块或文件的当前职责、入口、核心对象、调用方、下游、测试和对外契约。教程的历史章节必须解释当前仍存在的结构。

将扫描范围限制为目标目录或文件，以及入口、核心模型、关键测试等少量锚点。只有验证移动、重命名或跨模块重构时，才补查必要的相邻路径。

默认只使用当前检出版本可达的本地历史。不自动 fetch，不切换分支，不使用 `--all` 扩展到其他引用；用户明确要求时再扩大范围。

## 2. 检查可用性和版本边界

进行只读检查：

```text
git rev-parse --is-inside-work-tree
git status --short
git rev-parse --is-shallow-repository
git log -1 --format="%h %ad %s" --date=short
```

- 非 Git 仓库：省略历史章节，说明只能依据当前代码、测试和文档。
- 浅克隆：记录限制，将“首次引入”改为“最早可见状态”。
- 有未提交改动：将工作区快照和 `HEAD` 的提交历史分开描述。
- squash、历史重写或提交说明贫乏：只陈述补丁能证明的变化，动机标为推测或未知。

## 3. 筛选关键提交

模块目录先查看路径级摘要和变更规模：

```text
git log --date=short --format="%h%x09%ad%x09%s" --stat -- <module-path>
```

单文件追踪重命名：

```text
git log --follow --date=short --format="%h%x09%ad%x09%s" -- <file-path>
```

目录级 `--follow` 不可靠。模块移动时，从当前入口、核心模型和关键测试分别追踪，并验证候选提交：

```text
git show --find-renames --find-copies --stat <commit>
git show --find-renames --find-copies --format=fuller <commit> -- <relevant-paths>
git diff --find-renames <older>..<newer> -- <relevant-paths>
```

只在解释某一行当前约束的来源时使用 `git blame -L`，之后继续读取完整提交。blame 的作者和提交不能单独证明设计负责人或动机。

优先选择首次出现、关键缺陷修复、兼容或安全约束、边界或依赖方向变化、职责拆合、关键测试新增等节点。机械格式化和不影响理解的改名通常省略。能够回答起点、主要转折和当前护栏后停止。

## 4. 证据等级

| 标签 | 教程可以表达的内容 | 常见证据 |
| --- | --- | --- |
| 作者明确声明 | 作者或项目文档当时声明的目标与约束 | 提交正文、设计文档、仓库内关联说明 |
| 可观察演进 | 代码、测试、接口或边界实际发生的变化 | 补丁、测试、配置、迁移 |
| 推测 | 多项证据支持但没有直接陈述的解释 | 结构变化、命名、相邻缺陷修复 |
| 未知 | 本地历史无法支持的原因或因果关系 | 缺失记录、squash、浅克隆、仓库外讨论 |

提交主题只能证明作者如何概括提交。不要因为提交时间相邻就声称因果关系，也不要把 merge 提交自动当成设计决策点。

## 5. 判断设计护栏

只有以下两项同时成立，才写成“不应轻易破坏的设计护栏”：

1. 历史证据表明该变化用于修复缺陷、维持兼容、安全、数据一致性或明确架构约束。
2. 当前代码、测试、接口、数据格式或配置仍在实施或保护该约束。

只有历史证据时写成“历史设计意图，当前是否仍适用待确认”；只有当前复杂实现时写成“候选风险”。不要为所有遗留复杂度寻找合理化解释。

## 6. 教程章节结构

仅在历史模式启用时保留“演进与设计意图”，并采用：

1. **最初解决的问题**：说明最早可确认的职责；历史不完整时称为“最早可见状态”。
2. **关键里程碑**：每个节点说明发生了什么、作者声明或可推测的原因、可观察的代价。
3. **如何形成当前设计**：把历史节点连接到当前文件、接口和测试。
4. **修改护栏**：区分不要轻易破坏、可以安全调整、候选风险。
5. **未知项**：列出需要维护者、PR/issue 或更完整历史确认的内容。

每个历史节点至少记录短提交哈希、日期、主题和相关路径。存在符合项目约定且读者可访问的远程提交链接时可以使用；否则保留本地可搜索的提交标识。提交证据支持历史结论，但不自动意味着整篇教程固定在该版本。
