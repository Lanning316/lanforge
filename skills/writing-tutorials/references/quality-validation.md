# 教程质量校验

写完单文件教程或实质性章节后使用。确定性检查由脚本完成，内容质量由人工检查完成。

## 1. 运行脚本

```text
python <skill-root>/scripts/validate_tutorial.py <tutorial-path> --repo-root <project-root>
```

可选模式：

```text
--mode single
--mode chapter
--mode appendix
```

默认 `auto`：README、附录、规格和计划按非正文处理；其他 Markdown 按单文件正文处理。

脚本检查：

- 模板占位符。
- Markdown 围栏是否闭合。
- `file:///` 和常见本机绝对路径。
- 本地相对链接是否存在、是否逃出项目根目录。
- “💡 一句话记住”的数量和位置。
- 是否至少存在源码定位。
- 常见核心结构缺失警告。

警告不会导致失败；错误会返回非零退出码。

## 2. 人工内容检查

- [ ] 项目目标和教程范围清楚。
- [ ] 主流程从入口到结果连续，没有关键跳步。
- [ ] 每个核心结论能回到代码、测试或项目文档。
- [ ] 设计理由有证据；无证据时标为推测或实现观察。
- [ ] 代码片段足够小，并确实支持相邻解释。
- [ ] 术语首次出现时解释，后续命名一致。
- [ ] 图确实比文字更容易理解，并与正文一致。
- [ ] 知识框支持主线，没有为了数量而添加。
- [ ] 没有复制密钥、内部地址、用户数据或本机目录。

## 3. 不再使用的质量代理

以下指标不作为硬门槛：

- 固定行数。
- 固定知识框数量。
- 固定源码链接数量。
- 固定 Mermaid 图数量。
- 固定面试题数量。

小模块可以短，复杂模块可以拆章。质量取决于范围完整、证据准确和读者能否跟随，而不是字符计数。

## 4. 校验失败处理

- 残留占位符：补全或删除对应模板段落。
- 链接不存在：重新计算相对路径或改成纯文本定位。
- 绝对路径泄露：改成仓库相对路径或永久链接。
- 围栏未闭合：修复 Markdown 代码块。
- 总结数量错误：单文件只保留文末一个；多文件每个实质性章节一个。
- 结构警告：确认该节是否真的适用；不适用时可以保持省略。
