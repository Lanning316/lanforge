# 可移植源码链接规范

在教程中引用源码前使用。目标是让链接可验证、可分享，并避免泄露本机目录。

## 目录

1. 优先级
2. 远程永久链接
3. 仓库相对链接
4. 纯文本定位
5. 禁止形式
6. 行号维护

## 1. 优先级

按顺序选择：

1. 有可识别的 Web 远程仓库和 commit：使用远程永久链接。
2. 没有可用远程链接：使用从教程文件到源码文件的相对链接。
3. 渲染器不支持源码链接：使用仓库相对路径、符号和行号的纯文本定位。

不要同时复制多套链接，除非用户明确需要本地和远程两种阅读方式。

## 2. 远程永久链接

格式示例：

```markdown
[router.ts](https://github.com/example/project/blob/4f1a2b3/src/router.ts#L20-L45) 中的 `createRouter` 负责注册入口。
```

要求：

- URL 锚定完整 commit，而不是易变化的分支名。
- 链接文字使用 basename。
- 行范围只覆盖支持当前结论的代码。
- 文档开头记录源码基准 commit。
- 私有远程地址只在目标文档本来就允许内部共享时使用。

如果远程地址无法可靠转换为 Web URL，回退到相对链接，不猜测域名格式。

## 3. 仓库相对链接

格式示例：

```markdown
[router.ts](../../../src/router.ts) 中的 `createRouter`（`src/router.ts:20-45`）负责注册入口。
```

要求：

- 链接相对于教程 Markdown 文件计算。
- 括号中的定位使用仓库相对路径，便于搜索。
- 优先提供符号名；行号可能变化，不能只写行号。
- 相对路径不得逃出项目根目录。

## 4. 纯文本定位

无法生成可靠链接时写：

```markdown
源码定位：`src/router.ts:20-45`，符号 `createRouter`。
```

这比写一个无法打开的链接更可靠。

## 5. 禁止形式

默认禁止：

- `file:///...`
- `C:\Users\name\...`
- `/Users/name/...`
- `/home/name/...`
- 只写“大约在某文件附近”而没有符号或路径。
- 锚定 `main`、`master` 等可变分支却声称是永久链接。

绝对路径会换机器失效，并可能泄露用户名、磁盘结构和内部目录。

## 6. 行号维护

- 远程永久链接的行号与 commit 一起固定。
- 相对链接的行号可能漂移，因此同时写符号名。
- 教程更新时重新检查关键定位。
- 最终审查应验证所有本地相对链接；远程链接在网络不可用时至少验证 URL 结构和 commit。
